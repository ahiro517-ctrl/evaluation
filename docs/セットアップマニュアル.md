# セットアップマニュアル（clasp push 版）

このリポジトリのGASコードを `clasp push` でGoogleスプレッドシートに反映し、
評価シートを生成・運用するまでの手順。

- ソースコードは `src/` 配下（`*.gs` と `appsscript.json`）
- スプレッドシートに**バインドした**Apps Scriptプロジェクトに push する構成
- push 後、スプレッドシートのメニュー「評価運用」から全シートを自動生成する

---

## 0. 前提（初回だけ）

```bash
# Node.js が入っている前提
npm install -g @google/clasp   # clasp を入れる
clasp login                    # Googleアカウントで認証（ブラウザが開く）
```

> 初回は https://script.google.com/home/usersettings で
> 「Google Apps Script API」を ON にしておく。

---

## 1. スプレッドシートとApps Scriptプロジェクトを用意

評価シートはGASが**アクティブなスプレッドシートに**生成する。
そのため、スクリプトはスプレッドシートにバインドさせる。

1. Googleドライブで新規スプレッドシートを作成（名前は「評価シート_2026前期」など）。
2. メニュー **拡張機能 → Apps Script** を開く（空のバインド済みプロジェクトができる）。
3. Apps Scriptエディタ左の **プロジェクトの設定（⚙）** を開き、**スクリプトID** をコピーする。

---

## 2. ローカルに .clasp.json を作成

`.clasp.json.example` をコピーして、コピーしたIDを貼る。

```bash
cp .clasp.json.example .clasp.json
```

`.clasp.json` を編集:

```json
{
  "scriptId": "（手順1でコピーしたスクリプトID）",
  "rootDir": "src"
}
```

- `rootDir: "src"` により、push対象は `src/` 配下だけになる（docs等は送られない）。
- `.clasp.json` は環境固有なので `.gitignore` 済み（コミットしない）。

---

## 3. push する

```bash
clasp push
```

`src/` の `appsscript.json` と `constants.gs / build.gs / logic.gs / menu.gs` が
Apps Scriptプロジェクトに反映される。

> 既存のバインドプロジェクトに最初の `appsscript.json` を push する際、
> 「Manifest file has been updated…」の確認が出たら `y` で進める。
> 既存ファイルを上書きする旨の確認には `clasp push -f` を使う。

---

## 4. メニューから評価シートを生成

1. スプレッドシートを**リロード**する（数秒で上部に **評価運用** メニューが出る）。
2. **評価運用 → ① 評価シートを生成 / 再生成** を実行。
3. 初回は権限承認のダイアログが出る → 自分のアカウントで許可。
4. 対象期（例: `2026前期`）を入力すると、次の8シートが生成される。

| シート | 役割 |
|--------|------|
| 設定 | 制度マスタ（参照用・自動書き出し） |
| 名簿 | メンバー入力（ここから運用開始） |
| 粗利入力 | 半期粗利→倍率→判定（自動） |
| バリュー評価 | 9項目27点（自己／長） |
| スキル評価 | 10項目1〜5（自己／長） |
| 評価結果サマリ | 最終判定・改定額・改定後月給（自動） |
| 昇格・降格判定 | 連続条件の判定 |
| 履歴 | 確定値の蓄積 |

---

## 5. 運用の流れ（半期ごと）

制度スケジュールに対応した操作。

1. **名簿** にメンバーを入力（社員ID・氏名・区分・等級・B年次・現在月給など）。
   社員IDをキーに全シートが自動で連動する。
2. **粗利入力** の「実績半期粗利」を担当者が入力 → 経理が確定（倍率・判定は自動）。
3. **バリュー評価** … 自己評価 → ユニット長評価の順に入力（確定合計は長合計を既定採用）。
4. **スキル評価** … 同様に1〜5を入力。
5. **評価結果サマリ** で最終判定・改定額・改定後月給を確認（自動）。
6. **評価運用 → ② 昇格・降格を判定** を実行（履歴を見て連続条件を判定）。
   本人意思・アサイン体制・回復見られず は手入力してから実行する。
7. 評価会議で確定したら **評価運用 → ③ 当期を確定して履歴へ**。
   サマリの内容が「履歴」に1人1行追記される（同一期・同一IDは重複追記しない）。
8. 次の半期は、新しいスプレッドシートを作って同じ手順。
   ※ 連続条件（昇格3期/降格2期など）を使うため、**履歴は引き継ぐ**。
   前ブックの「履歴」シートの内容を、新ブックの「履歴」シートに貼り付けておく。

> 対象期を変えるだけなら **評価運用 → 対象期を変更**。

---

## 6. 制度の数値を変えるとき

判定基準・改定額・等級レンジなどの制度値は **`src/constants.gs`** が唯一の正。

1. `src/constants.gs` を編集。
2. `clasp push`。
3. スプレッドシートで **評価運用 → ① 評価シートを生成 / 再生成**。
   - ⚠ 再生成は全シートを作り直すため、入力済みデータは消える。
     運用中のブックでは、別ブックで検証してから反映するか、`設定`シートを手で直す。

---

## 7. よくあるつまずき

| 症状 | 対処 |
|------|------|
| メニュー「評価運用」が出ない | スプレッドシートをリロード。バインド先のスクリプトに push できているか確認 |
| `Script function not found: onOpen` | `src/menu.gs` が push されているか、`clasp push` の対象（rootDir）を確認 |
| push で権限エラー | `clasp login` のやり直し、Apps Script API が ON か確認 |
| `User has not enabled the Apps Script API` | https://script.google.com/home/usersettings でON |
| 判定が出ない | 名簿の社員ID・等級が入っているか。粗利の実績・基準が埋まっているか |
| 昇格/降格の連続判定が×のまま | 履歴シートに過去期のデータがあるか。②の判定を実行したか |

---

## 補足：スタンドアロンで使う場合

スプレッドシートにバインドせず、独立したGASプロジェクトでも動かせる
（その場合は手順1でドライブから直接 Apps Script を新規作成し、`buildWorkbook()` を
実行すると、実行中にひもづくスプレッドシートに生成される）。
ただしメニュー（onOpen）はバインド時のみ表示されるため、**バインド構成を推奨**。
